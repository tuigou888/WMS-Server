## P2-4: 引入 Java enum 替代 orderStatus/payStatus/payType/orderAction 魔法字符串

### 新建 4 个枚举类（放在 `com.wms.model.entity.market` 包下，与实体同级）

1. **`MarketOrderStatus.java`** — `PENDING, AUDITED, SHIPPED, COMPLETED, CANCELLED, REJECTED`
2. **`MarketPayStatus.java`** — `UNPAID, PAID, REFUNDED`
3. **`MarketPayType.java`** — `PAY_ONLINE, CASH_ON_DELIVERY, CREDIT`
4. **`MarketOrderAction.java`** — `CREATE, PAY, AUDIT, SHIP, COMPLETE, CANCEL, REFUND`

每个枚举类提供 `@JsonValue` 序列化（输出 `name()`）和 `@JsonCreator` 反序列化（按 name 匹配，大小写不敏感容错），确保 API 线上协议不变（JSON 中仍是 `"PENDING"` 等字符串）。

### MarketOrder 实体改造

- `orderStatus` 字段类型 `String` → `MarketOrderStatus`，加 `@Enumerated(EnumType.STRING)`，默认值 `MarketOrderStatus.PENDING`
- `payStatus` 字段类型 `String` → `MarketPayStatus`，加 `@Enumerated(EnumType.STRING)`，默认值 `MarketPayStatus.UNPAID`
- `payType` 字段类型 `String` → `MarketPayType`，加 `@Enumerated(EnumType.STRING)`，默认值 `MarketPayType.PAY_ONLINE`
- getter/setter 签名改为对应枚举类型
- 更新 Javadoc 注释

### MarketOrderLog 实体改造

- `action` 字段类型 `String` → `MarketOrderAction`，加 `@Enumerated(EnumType.STRING)`
- getter/setter 签名改为 `MarketOrderAction`

### MarketService.java 引用点替换

将所有 `"PENDING".equals(...)` → `MarketOrderStatus.PENDING.equals(...)`，`order.setOrderStatus("AUDITED")` → `order.setOrderStatus(MarketOrderStatus.AUDITED)` 等，覆盖：
- `createOrder`: setOrderStatus/setPayStatus
- `prepay`: 状态比较
- `confirmMockPay`: 状态比较
- `markPaid`: 状态比较 + setOrderStatus/setPayStatus
- `refund`: payStatus 比较 + setPayStatus
- `cancelByUser`: 状态比较 + setOrderStatus
- `audit`: 状态比较 + setOrderStatus + isPayOnline 改用 `MarketPayType.PAY_ONLINE`
- `ship`: 状态比较 + setOrderStatus
- `complete`: 状态比较 + setOrderStatus
- `forceCancel`: 状态比较 + setOrderStatus
- `new MarketOrderLog(id, "CREATE", ...)` → `new MarketOrderLog(id, MarketOrderAction.CREATE, ...)`

### MarketAdminController.java 引用点替换

- `stats()` 中 `List.of("PENDING", ...)` → `List.of(MarketOrderStatus.values())` 或 `Arrays.stream(MarketOrderStatus.values()).map(Enum::name).toList()`，`countByStatus` 入参保持 String（JPQL 用 name 比较）

### MarketOrderRepository.java JPQL

- `@Query` 中的 `'COMPLETED'`、`'CANCELLED'` 字面量保持不变（JPA `@Enumerated(STRING)` 持久化的就是枚举 name，DB 列值仍为 `"COMPLETED"`，JPQL 字符串比较仍然有效）
- `countByStatus(String status)` 方法签名保持 String（控制器传入枚举 name 即可），或改为接收 `MarketOrderStatus` 后在调用处 `.name()` — 选择保持 String 签名以减少改动面

### MarketController.java

- `view(MarketOrder)` 中 `o.getOrderStatus()` / `o.getPayStatus()` / `o.getPayType()` 直接放入 Map — 枚举的 `@JsonValue` 会自动序列化为 name 字符串，无需改动

### 测试文件更新

- `MarketServiceIntegrationTest.java`: 所有 `assertEquals("PENDING", ...)` → `assertEquals(MarketOrderStatus.PENDING, ...)`；`setPayType("PAY_ONLINE")` → `setPayType(MarketPayType.PAY_ONLINE)`；action 字符串 `"PAY"/"AUDIT"` → `MarketOrderAction.PAY` 等；`orders.countByStatus("PENDING")` → `orders.countByStatus(MarketOrderStatus.PENDING.name())`
- `WechatPayServiceTest.java`: `setPayType("PAY_ONLINE")` → `MarketPayType.PAY_ONLINE`，`setOrderStatus("PENDING")` → `MarketOrderStatus.PENDING`，`setPayStatus("UNPAID")` → `MarketPayStatus.UNPAID`
- `MarketControllerTest.java` / `WechatPayNotifyControllerTest.java`: 同理更新断言中的字符串为枚举或 `.name()`

### 前端无需改动
枚举 `@JsonValue` 输出 `name()`，JSON 中仍是 `"PENDING"` 等字符串，前端 `=== 'PENDING'` 比较不受影响。

## P2-10: checkout.vue 增加挂账(CREDIT)入口，仅管理员可见

### 小程序端改造

1. **`checkout.vue`** — `payTypes()` computed 改为根据用户角色动态返回：
   - 基础选项：`微信支付(PAY_ONLINE)`、`货到付款(CASH_ON_DELIVERY)`
   - 若 `useUserStore().user?.role === 'ADMIN'`，追加 `挂账(CREDIT)` 选项
   - 引入 `useUserStore`（已 import 但未使用 role）

2. **后端无需改动** — `MarketService.audit()` 已处理非 PAY_ONLINE 订单（CASH_ON_DELIVERY 和 CREDIT 都走审核扣库存 + 置 PAID 路径），`ship()` 已校验 `payStatus == PAID`。CREDIT 订单经审核后 payStatus 置 PAID，可正常发货。
