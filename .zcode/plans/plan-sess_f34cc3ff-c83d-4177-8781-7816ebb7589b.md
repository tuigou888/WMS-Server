# 商城小程序微信支付接入实现计划

基于微信支付官方文档（APIv3 / 普通商户 / 小程序支付）与现有 WMS 代码结构制定。所有接口字段、流程严格对齐官方文档 `4012791897`（下单）、`4012791898`（调起）、`4012791902`（支付回调）、`4012791900`（查单）、`4012791903`（退款）。

## 设计原则
- **真实链路 + mock 兜底**：代码按真实微信支付流程完整实现，但加 `wechat.pay.mock` 开关。未配置商户号时（dev/test）走本地模拟：prepay 返回 mock 调起参数 → 前端跳过 `requestPayment` 直接调「模拟支付确认」接口落单。生产置 `false` 且必须配真实参数，否则拒绝。沿用现有 `WechatService` 的 mock 校验风格（生产误开抛异常）。
- **扣库存时机后移**：把 `MarketService.pay()` 里的 `deductStock` 迁到「支付成功」处理，prepay 仅调微信下单不落状态，避免下单未付款就占库存。
- **回调幂等**：回调按 `transaction_id` 幂等 + 订单状态二次校验（仅 PENDING/UNPAID 才处理），应对微信重试。
- **回调不走 ApiResponse**：回调 controller 直接返回 200/4xx + `{code,message}`，不套统一壳，避免微信侧解析失败重试。
- **openid 复用**：JSAPI 下单需 openid，已存在 `UserAccount.openid`，后端 `user.getOpenid()` 直接取；账号密码登录无 openid 的用户不能发起微信支付，提示「请用微信登录」。

## 一、后端改造（wms-server）

### 1. pom.xml 新增官方 SDK 依赖
```xml
<dependency>
    <groupId>com.github.wechatpay-apiv3</groupId>
    <artifactId>wechatpay-java</artifactId>
    <version>0.2.14</version>
</dependency>
```
（官方维护，封装 V3 签名/验签/AES-GCM 解密/平台证书自动下载，比手写 HTTP 安全）

### 2. application.yml 新增支付配置段
```yaml
wechat:
  appid: ${WECHAT_APPID:}
  secret: ${WECHAT_SECRET:}
  mock: ${WECHAT_MOCK:false}
  pay:
    mock: ${WECHAT_PAY_MOCK:false}        # 仅 dev/test 允许；生产禁开
    mch-id: ${WECHAT_PAY_MCH_ID:}          # 商户号
    mch-serial-no: ${WECHAT_PAY_MCH_SERIAL:} # 商户API证书序列号
    api-v3-key: ${WECHAT_PAY_API_V3_KEY:}  # APIv3密钥（32位，回调解密用）
    private-key-path: ${WECHAT_PAY_KEY_PATH:} # 商户私钥 apiclient_key.pem 路径
    wechat-pay-public-key-id: ${WECHAT_PAY_PUB_KEY_ID:} # 微信支付公钥ID（PUB_KEY_ID_xxx）
    wechat-pay-public-key-path: ${WECHAT_PAY_PUB_KEY_PATH:} # 微信支付公钥 pem 路径
    notify-url: ${WECHAT_PAY_NOTIFY_URL:}  # 回调地址，如 https://your-domain/api/v1/market/pay/notify
```

### 3. MarketOrder 实体新增字段（JPA ddl-auto:update 自动加列）
```java
private String transactionId;     // 微信支付订单号（回调回填，长度32）
private String prepayId;          // 预支付会话标识（2h有效，长度64）
private String refundNo;          // 商户退款单号
private String refundReason;
private BigDecimal refundAmount;
private LocalDateTime refundedAt;
```
更新 view() 输出 `transactionId`（退款相关字段按需输出）。

### 4. MarketOrderRepository 新增方法
```java
Optional<MarketOrder> findByOrderNo(String orderNo);  // 回调按 out_trade_no 查单
```

### 5. 新增 WechatPayConfig（配置类 + SDK 客户端）
`service/market/WechatPayConfig.java`：
- `@ConditionalOnProperty(wechat.pay.mock, havingValue=false, matchIfMissing=true)` 才初始化真实 SDK 客户端，避免未配置时启动失败。
- 构建 `RSAPublicKeyConfig`（用微信支付公钥验签，优于平台证书方案），暴露 `JsapiService`（下单/查单/关单）和 `RefundService`（退款）Bean。
- 暴露配置元数据：appid、mchId、notifyUrl。

### 6. 新增 WechatPayService（核心支付逻辑）
`service/market/WechatPayService.java`，方法：
- `PrepayResult prepay(MarketOrder order, UserAccount user)`：
  - mock 分支：生成 mock prepayId（`MOCK_订单号_时间戳`），返回 mock 调起参数。
  - 真实分支：调 `JsapiServiceExtension.prepay()`，传 appid/mchid/description(取首个商品名)/out_trade_no(=orderNo)/amount.total(分，`totalAmount×100` HALF_UP)/payer.openid/notify_url。回填 `prepayId` 落库。
  - 用微信支付官方 `JsapiServiceExtension` 生成调起支付签名（`signWithRequestPayment`），返回 `{timeStamp,nonceStr,package:"prepay_id=xxx",signType:"RSA",paySign,prepayId}`。
- `Transaction handleNotify(String serial, String nonce, String timestamp, String signature, String body)`：
  - mock 分支：直接解析 body（模拟回调）。
  - 真实分支：用 `NotificationParser.parse()` 验签 + AES-GCM 解密得 `Transaction`。
  - 返回解密后的 Transaction（含 out_trade_no/transaction_id/trade_state/amount）。
- `Transaction queryByOutTradeNo(String orderNo)`：调 `JsapiServiceExtension.queryOrderByOutTradeNo()`。
- `Refund refund(MarketOrder order, String reason)`：调 `RefundService.create()`，退款单号 `orderNo + "R" + 时间戳`，金额=原支付金额。

### 7. MarketService 改造
- 把原 `pay()` 拆分：
  - 新增 `markPaid(MarketOrder order, String transactionId, String operator)`：幂等校验（若已 PAID 直接返回），执行 `deductStock` + 状态置 `AUDITED/PAID` + `paidAt` + 写 PAY 日志。供回调与模拟支付确认调用。
  - 新增 `confirmMockPay(UserAccount user, Long orderId)`：mock 模式专用，调 `markPaid`，transactionId 用 `MOCK_订单号`。
  - `pay()` 保留为 mock 兼容入口（仅 mock 模式可用，内部调 confirmMockPay），真实模式下调用 prepay。
- 新增 `refund(Long orderId, String reason, String operator)`：ADMIN 调用，校验已支付，调 `WechatPayService.refund()`，退款流水记录；成功回填 refund 字段、payStatus 置 REFUNDED（待回调确认/或同步返回成功即置）。退款需回滚已扣库存（复用 `rollbackStock`）。

### 8. Controller 改造
**MarketController**（小程序端 `/market`）：
- 改造 `POST /orders/{id}/pay` → `POST /orders/{id}/prepay`：返回调起支付参数（mock 模式返回 mock 参数 + mock=true 标识）。校验：订单归属、状态 PENDING、用户有 openid（真实模式）。
- 新增 `POST /orders/{id}/mock-pay`：仅 mock 模式可用，调用 `confirmMockPay` 落单（前端在 mock 模式跳过 `requestPayment` 直接调此接口）。
- 保留 `cancel`、`receive` 不变。

**新增 WechatPayNotifyController**（`controller/market/WechatPayNotifyController.java`，路径 `/market/pay`）：
- `POST /notify`：接收微信回调。**不套 ApiResponse**，直接返回 `200`（成功）或 `4xx + {code:"FAIL",message:...}`（失败）。
  - 读取请求头 `Wechatpay-Serial/Timestamp/Nonce/Signature`，调用 `WechatPayService.handleNotify()`。
  - 验签失败/解密失败 → 返回 4xx FAIL。
  - 解密成功 → 取 out_trade_no 查单 → 调 `MarketService.markPaid(transactionId, "wxpay")`（已幂等）→ 返回 200。
  - 异常返回 5xx FAIL 触发微信重试。

**MarketAdminController**：
- 新增 `POST /orders/{id}/refund`：ADMIN 发起退款，body `{reason}`。

### 9. SecurityConfig 放行回调
在 `permitAll` 列表加 `/market/pay/notify`（微信服务器不带 token）。
```
authz.requestMatchers("/auth/login","/auth/wx-login","/auth/wx-bind","/health","/market/pay/notify").permitAll();
```

## 二、小程序前端改造（wms-shopping-miniapp）

### 1. src/api/market.js
```js
export const orders = {
  create, list, detail,
  prepay: (id) => http.post(`/market/orders/${id}/prepay`),   // 拉起支付参数
  mockPay: (id) => http.post(`/market/orders/${id}/mock-pay`), // mock 模式确认支付
  cancel, receive,
}
```

### 2. 新增 src/utils/pay.js（统一拉起支付工具）
封装 `requestPayment(orderId)`：
- 调 `orders.prepay(id)` 拿参数。
- 若返回 `mock=true`：直接调 `orders.mockPay(id)` → 返回成功。
- 否则调 `uni.requestPayment({timeStamp,nonceStr,package,signType:'RSA',paySign})`。
  - success：调「查单」或直接 reload（后端回调已落单，前端仅刷新展示）。
  - fail：区分 `requestPayment:fail cancel`（用户取消，提示「已取消支付」）与其他失败（提示错误）。

### 3. order-detail.vue 改造
- `pay()` 方法改为调用 `pay.js` 的 `requestPayment`，成功后 `this.load()` 刷新状态。

### 4. orders.vue 改造
- `payOrder()` 同样改用统一 `pay.js`。

### 5. checkout.vue
- 支付方式文案「在线支付(模拟)」→「微信支付」。
- 下单后跳转 order-detail 由详情页承担支付（保持现状，不在结算页直接支付，避免 prepay 与下单时序耦合）。

### 6. manifest.json
- 不强制改 appid（真实联调时用户自行填）。在代码注释/文档说明：接入真实微信支付需在 `manifest.json` 的 `mp-weixin.appid` 填真实小程序 appid，且与后端 `wechat.appid` 一致。

## 四、验证步骤
1. `cd wms-server && mvn -DskipTests package`（验证 SDK 依赖拉取、编译）。
2. `mvn test`（确保现有 4 个测试类不回归；微信支付逻辑因依赖外部凭证，单测仅覆盖 mock 分支与幂等校验）。
3. mock 模式联调：`WECHAT_PAY_MOCK=true mvn spring-boot:run`，小程序登录（微信登录或 mock 登录）→ 下单 → prepay 返回 mock 参数 → mock-pay 落单 → 订单变 AUDITED/PAID。
4. 真实模式：配齐 `WECHAT_PAY_*` 环境变量，用微信开发者工具登录真实小程序 → 下单 → 拉起微信收银台 → 支付 → 回调落单 → 查单。
5. `cd wms-shopping-miniapp && npm run build:mp-weixin`（验证前端编译）。

## 五、不涉及范围
- 不改 docker-compose / README 描述的 Redis/MinIO/Nginx（按 AGENTS.md，仓库无对应服务）。
- 不引入交易类小程序「发货管理功能」（属公众平台合规，需另行接入，文档已提示；代码层留 TODO 注释）。
- 退款资金实际到账以微信侧为准，本实现只做接口调用与状态记录。
- 不动 OCR mock、不动核心进销存单据逻辑。
