## 三、Web 端浏览器兼容性

### 3.1 已验证

- **Chrome（google-chrome 最新版，headless）**：38 项 UI 回归全部通过——登录、按角色渲染菜单（ADMIN/WAREHOUSE 双角色断言）、16 个页面路由切换、表格渲染与分页、新建/审核/执行弹窗、商城看板。回归覆盖同时验证了本次新增的表格 loading 态未引入渲染回归。
- **构建层面**：Vite 6 生产构建通过；`styles.css` 使用的特性（CSS 自定义属性、`calc()`、flex/grid、`env(safe-area-inset-bottom)` 仅限小程序端、`@media` 查询、`backdrop-filter` 带 `-webkit-` 前缀、`prefers-reduced-motion`）均为 Chrome/Firefox/Safari/Edge 最新版共同支持的基线特性，无浏览器特定风险点。

### 3.2 未实测（本环境无对应浏览器，给出风险评估）

| 浏览器 | 风险评估 | 说明 |
| --- | --- | --- |
| Firefox 最新版 | 低 | Ant Design Vue 4 官方支持 Firefox；本项目 CSS 无 Firefox 不支持的特性（无 `::-webkit-scrollbar` 依赖逻辑） |
| Safari 最新版 | 低 | 需关注 `100dvh`（如使用）回退——本次审查确认全局样式使用 `100vh` + flex 布局，Safari 正常；日期控件使用 dayjs，无原生 date input 依赖 |

### 3.3 响应式断点验证

- `styles.css` 定义了 `@media (max-width: 1024px)` / `@media (max-width: 767px)` 两档：侧边栏折叠为抽屉、`.page` 内边距收窄、表格启用横向滚动（`.ant-table` 最小宽 680px）。
- 本次修改的 PurchaseRequestsPage 明细行增加 `flex-wrap` 后，窄屏下弹窗明细不再溢出（静态验证 + 构建通过）。

## 六、测试中发现并修复的问题（回归阶段）

| # | 现象 | 根因 | 修复 |
| --- | --- | --- | --- |
| 1 | `GET /reports/profit` HTTP 500，利润报表页报错 | Spring Data 把单行聚合结果包装成 `Object[1]`，控制器取 `totals[1]` 越界 | ReportController 解包内层数组 |
| 2 | 所有 `@Idempotent` 写接口（单据/调拨/盘点/扫码创建）HTTP 500 | `IdempotencyAspect` 用 `@annotation(idempotent)` 参数绑定，运行时抛 `JoinPointMatch was NOT bound` | 改为全限定名 pointcut + 通知内反射取注解 |
| 3 | 更新用户仓库授权 HTTP 400"数据冲突"（Web 用户管理页同触发） | Hibernate flush 时 INSERT 先于 DELETE，撞 `(user_id, warehouse_id)` 唯一约束 | `replaceAssignments` 删除后强制 `flush()` |
| 4 | API 回归 22 项失败 | 回归脚本未随接口契约更新（缺 `Idempotency-Key` 头、库存分页断言取错对象、操作员未授权新仓库、新用户未配仓库） | 同步更新 `run_api_regression.py` |
| 5 | UI 回归 3 项失败 | 脚本菜单断言使用改名前的"二维码与 Excel" | 同步为"二维码与电子表格" |
| 6 | `mvn test` 33 errors（MarketControllerTest） | 上一提交为商城写接口加 `@Idempotent` 后，测试基座 `Harness` 直连 Controller 调用未携带幂等键 | `Harness` 注入每次读取返回新值的 `Idempotency-Key` |
| 7 | `mvn test` 1 failure（发货未累计销量断言） | JPQL 批量更新绕过持久化上下文一级缓存，`@Transactional` 测试读到旧值（生产行为正确） | 测试重读前 `entityManager.clear()` |

## 七、结论

- 三端全部构建通过；Web 端 Chrome 真实回归 38/38、API 真实链路 72/72 全绿。
- 本次前端修改本身未引入任何回归；回归中发现的问题均为**既有后端缺陷**（上个提交引入的幂等切面 500、报表 500、用户仓库授权约束冲突）与**测试脚本过时**，已一并修复。
- 小程序端真机项（iOS/Android 主流机型冒烟）因环境限制未执行，已给出机型清单与重点验证项（见 5.2），构建产物可直接导入微信开发者工具复验。
